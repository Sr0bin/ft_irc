Diagramme de classes du serveur

Architecture événementielle autour d'un seul poll(). Les classes abstraites (violet) marquent les points d'extension ; les concrètes (ardoise) portent l'état et la mécanique.

Classe abstraite — point d'extension
Classe concrète — état / mécanique
◆──composition (possède & détruit)
◇──agrégation (référence sans posséder)
──▷héritage
┄┄>dépendance (produit / consomme)
classDiagram
direction TB

class Server {
  -int _port
  -string _password
  -int _listenFd
  -map~Client~ _clients
  -map~Channel~ _channels
  -AMultiplexer _mux
  -CommandDispatcher _dispatcher
  +run() void
  +acceptClient() void
  +disconnectClient(int fd) void
  +getClientByNick(nick) Client
  +getChannel(name) Channel
  +getOrCreateChannel(name) Channel
}

class Client {
  -int _fd
  -string _inBuffer
  -string _outBuffer
  -string _nickname
  -string _username
  -State _state
  -set~Channel~ _channels
  +appendInput(data) void
  +extractLine(out) bool
  +queueReply(msg) void
  +hasPendingOutput() bool
  +isRegistered() bool
  +prefix() string
}

class Channel {
  -string _name
  -string _topic
  -string _key
  -size_t _userLimit
  -bool _inviteOnly
  -bool _topicRestricted
  -set~Client~ _members
  -set~Client~ _operators
  -set~Client~ _invited
  +addMember(c) void
  +removeMember(c) void
  +isOperator(c) bool
  +promote(c) void
  +canJoin(c, key) bool
  +broadcast(msg, except) void
}

class Message {
  -string _prefix
  -string _command
  -vector~string~ _params
  +getCommand() string
  +getParam(i) string
  +paramCount() size_t
}

class Parser {
  +parse(rawLine)$ Message
}

class CommandDispatcher {
  -map~ACommand~ _commands
  +registerCommand(cmd) void
  +dispatch(client, msg) void
}

class ACommand {
  <>
  #Server _server
  +execute(Client, Message)* void
  +minParams() size_t
  +requiresRegistration() bool
}

class JoinCommand {
  +execute(Client, Message) void
}

class AMultiplexer {
  <>
  +watch(fd)* void
  +unwatch(fd)* void
  +setWriteInterest(fd, on)* void
  +wait(events)* int
}

class PollMultiplexer {
  -vector~pollfd~ _fds
  +watch(fd) void
  +unwatch(fd) void
  +setWriteInterest(fd, on) void
  +wait(events) int
}

Server "1" *-- "0..n" Client : possede par fd
Server "1" *-- "0..n" Channel : possede par nom
Server "1" *-- "1" CommandDispatcher
Server "1" o-- "1" AMultiplexer
PollMultiplexer --|> AMultiplexer
JoinCommand --|> ACommand : x11 commandes
CommandDispatcher "1" o-- "n" ACommand : map nom vers handler
Channel "0..n" o-- "0..n" Client : non possede
Parser ..> Message : produit
CommandDispatcher ..> Message : consomme
Relation clé à retenir : Server possède les Client et Channel (composition) ; Channel ne fait que les référencer (agrégation). Un client qui se déconnecte doit être retiré de tous ses channels avant le delete — sinon dangling pointer.
